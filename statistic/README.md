# Статистика проекта «Разработка УП» (Vikunja)

FastAPI-сервис с веб-дашбордом: статистика выполнения задач проекта «Разработка УП»
из Vikunja с разбивкой по **дням / неделям / месяцам** и разрезами **по исполнителям**.

## Возможности

- выбор **периода** (дата начала — дата конца) или **диапазоном месяцев** «с … по …»
  с быстрыми пресетами (этот месяц, прошлый месяц, этот год);
- выбор **интервала разбивки**: день, неделя, месяц (по умолчанию месяц);
- **сводный график**: выполнено и создано за период + накопительный итог;
- графики **по людям**: кто сколько сделал (выполнено/создано), доля каждого,
  динамика по интервалам, среднее время выполнения задачи;
- график **по станкам (меткам)** с объединением похожих названий
  («пума»/«puma»/«Пума 1» → Пума, «са3м» → Саста 3м, «mynx» → Фрезер ЧПУ Минкс и т.д.);
- список задач за период со ссылками на задачи в Vikunja и сортировкой по колонкам, индикатор загрузки;
- **быстрая работа с данными**: страницы Vikunja грузятся параллельно (до 6
  одновременно), фоновая предзагрузка кэша при старте и по TTL, кэш на диске
  (по умолчанию 5 минут), кнопка «Обновить данные» для принудительного
  перечитывания API; параллельные обновления не дублируют загрузку.

## Быстрый старт

```bash
cd statistic
pip install -r requirements.txt        # или используйте .venv родительского проекта

# 1) впишите токен в .env (см. ниже)
# 2) запуск
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001
```

Откройте в браузере: **http://127.0.0.1:8001**

Интерактивная документация API: http://127.0.0.1:8001/docs

## Настройка токена

1. Зайдите в Vikunja: vikunja.ru → *Настройки* → *API-токены* (API Tokens).
2. Создайте токен (права на чтение проектов и задач).
3. Впишите его в файл `.env`:

```
VIKUNJA_TOKEN=paste_your_token_here
```

Остальные параметры `.env`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VIKUNJA_TOKEN` | — | API-токен Vikunja (обязательно) |
| `VIKUNJA_BASE_URL` | `https://vikunja.ru` | адрес API Vikunja (в Docker переопределяется на `http://vikunja_app:3456`) |
| `VIKUNJA_PUBLIC_URL` | `VIKUNJA_BASE_URL` | публичный адрес веб-интерфейса Vikunja — по нему строятся ссылки на задачи в браузере |
| `PROJECT_ID` | `1` | id проекта «Разработка УП» |
| `TZ` | `UTC` | часовой пояс для границ дня/недели/месяца (например `Asia/Yekaterinburg`) |
| `CACHE_TTL` | `300` | время жизни кэша задач, секунд (0 — отключить) |
| `LOG_LEVEL` | `INFO` | уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `AUTH_USER` | — | логин базовой HTTP-аутентификации дашборда |
| `AUTH_PASS` | — | пароль базовой HTTP-аутентификации дашборда |
| `DOMAIN` | `vikunja.ru` | домен сервиса для docker-compose/Traefik |
| `SUBDOMAIN` | `stat` | поддомен сервиса (итог: `stat.vikunja.ru`) |
| `SERVICE_PORT` | `8001` | порт, на котором приложение слушает внутри контейнера |

Если токен не задан, но в папке `cache/` есть ранее скачанные задачи — сервис
работает в офлайн-режиме на кэше.

Если заданы **оба** поля `AUTH_USER` и `AUTH_PASS` — доступ ко всему сервису
(страницы, API, статика, `/docs`) только по логину и паролю: браузер сам
покажет окно входа. Пустые поля отключают аутентификацию.

## Запуск в Docker (за Traefik)

Сервис публикуется как **https://stat.vikunja.ru** через Traefik из
`docker-compose.traefik.yml` (сеть `traefik_proxy-network`). Домен, поддомен
и порт задаются в `.env` (`DOMAIN`, `SUBDOMAIN`, `SERVICE_PORT`).

```bash
cd statistic
docker compose up -d --build
```

- образ собирается из `Dockerfile` (python:3.12-slim, uvicorn на порту `SERVICE_PORT`);
- все переменные из `.env` попадают в контейнер через `env_file`;
- **API Vikunja вызывается по внутренней сети Docker** (`http://vikunja_app:3456`,
  переопределяется в `docker-compose.yml`), а ссылки на задачи в браузере
  строятся по `VIKUNJA_PUBLIC_URL` (`https://vikunja.ru`);
- кэш задач лежит в `./cache` (volume) и переживает перезапуск контейнера;
- Traefik сам выпускает сертификат Let's Encrypt (websecure, `certresolver=le`)
  и делает редирект HTTP → HTTPS;
- healthcheck контейнера проверяет `/health` с учётом Basic Auth.

```bash
docker compose logs -f statistic   # логи
docker compose down                # остановить
```

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | дашборд с графиками |
| GET | `/api/meta` | проект, общее число задач, диапазон дат |
| GET | `/api/stats?start=YYYY-MM-DD&end=YYYY-MM-DD&interval=day\|week\|month` | статистика |
| GET | `/api/tasks?start=...&end=...` | задачи за период |
| GET | `/health` | проверка работоспособности |

Пример:

```bash
curl -u AUTH_USER:AUTH_PASS "http://127.0.0.1:8001/api/stats?start=2025-11-01&end=2025-12-31&interval=week"
```

## Правила подсчёта

- **Выполнено** — задача закрыта в периоде (по `done_at`; если поле пустое — по `updated`).
- **Создано** — задача создана в периоде (по `created`).
- Задача с несколькими исполнителями засчитывается **каждому**.
- Задачи без исполнителя попадают в категорию «Без исполнителя».
- **Среднее время выполнения** = разница между `done_at` и `created` закрытых задач.
- Неделя начинается с понедельника; границы интервалов считаются в часовом поясе `TZ`.
